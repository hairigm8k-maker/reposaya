CLI Documentation

Deploy static websites to HairiHosting from your terminal in seconds. No browser, no uploads — just one command.

What you'll learn: install the CLI, get an API key, and deploy your first site in under 2 minutes.

Overview

The hh-cli-deploy package gives you a command-line interface for HairiHosting. It works on any platform — Termux (Android), Linux, macOS, Windows.

What you can do:

  • Deploy a folder of HTML/CSS/JS to yourname.hairiamri.buzz
  • Update existing sites with a single command
  • Upload images automatically
  • Manage your sites from the terminal
  • Integrate with CI/CD pipelines

Installation

Prerequisites

  • Node.js 14+ — download here
  • npm — included with Node.js

Termux (Android):

bash 
pkg install nodejs

Install the CLI globally:

bash 
npm install -g hh-cli-deploy

Verify installation:

bash 
hh --version
# → 1.0.4

Quick Start

Deploy your first site in 3 steps.

1

Get your API key

Open the API Keys page in your dashboard and create a new key:

Open API Keys →

Copy the key (starts with hh_live_). You'll only see it once.

2

Login

bash 
hh login hh_live_xxxxxxxxxxxxx
# → ✓ Logged in as you@example.com
3

Deploy

Navigate to your project folder and run:

bash 
cd my-website
hh deploy mysite

Your site is now live at https://mysite.hairiamri.buzz 🎉

Tip: If you don't provide a subdomain, the CLI will prompt you for one.

Commands Reference

login

Save your API key for future deploys.

bash 
hh login <api-key>

The API key is stored in ~/.hairihosting/config.json with chmod 600 for security. You can also set it via environment variable:

bash 
export HAIRIHOSTING_API_KEY=hh_live_xxx

deploy

Deploy the current folder to a subdomain.

bash 
hh deploy [subdomain] [options]

Options

FlagDescription
--dir <path>Folder to deploy (default: .)
--overwriteReplace existing site fully (delete old files)
--mergeOnly update provided files, keep the rest
--no-publishUpload but keep as draft (not live)

Behavior

  • Auto-inject: CSS files get injected into <head> if not already linked
  • Images: Uploaded automatically (max 1.5 MB each)
  • Conflict: If the subdomain exists, CLI prompts Overwrite (o) / Merge (m) / Cancel (c)
  • Default: Site is published live after deploy (--no-publish to keep draft)

list

List all your sites and their status.

bash 
hh list

# → Your sites (3)
#   portfolio.hairiamri.buzz    ● LIVE
#   kopi.hairiamri.buzz         ● LIVE
#   draft-site.hairiamri.buzz   ○ DRAFT

delete

Delete a site and all its files permanently. Prompts for confirmation.

bash 
hh delete old-project

whoami

Show the current logged-in account.

bash 
hh whoami

# → Email: you@example.com
#   Name:  Your Name
#   Role:  user

logout

Remove the saved API key from your machine.

bash 
hh logout

Examples

Deploy a simple static site

bash 
cd ~/my-portfolio
hh deploy

Deploy from a build output folder

bash 
npm run build
hh deploy portfolio --dir ./dist

Update existing site (overwrite)

bash 
hh deploy mysite --overwrite

Deploy as draft (not published)

bash 
hh deploy staging --no-publish

CI/CD Integration

Automate deploys from GitHub Actions, GitLab CI, or any pipeline.

GitHub Actions

.github/workflows/deploy.yml 
name: Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm install -g hh-cli-deploy
      - run: hh deploy mysite --overwrite
        env:
          HAIRIHOSTING_API_KEY: ${{ secrets.HAIRIHOSTING_API_KEY }}
Security tip: Always use environment variables in CI, not hh login. Store the API key as a secret in your CI provider.

FAQ

Where do I get an API key?

Go to Dashboard → API Keys, click + Create API Key, and copy the key. You'll only see it once.

What's the file size limit?

Each image is limited to 1.5 MB. Files larger than this are skipped with a warning.

Can I use a custom domain?

Yes. Add the domain from the dashboard first, then deploy to that site. The CLI deploys to *.hairiamri.buzz subdomains, but custom domains work automatically once verified.

How do I roll back a deploy?

Redeploy from a previous version of your folder. There's no automatic rollback — keep your project in Git and checkout the old commit, then deploy.

What files get uploaded?

HTML, CSS, JS, and images (PNG/JPG/JPEG/GIF/WebP/SVG/ICO). Other files (JSON, MD, etc.) are skipped. CSS files are auto-injected into <head> if not already linked.

Is my API key safe?

Yes. The config file ~/.hairihosting/config.json is stored with chmod 600 (owner-only). Never commit it to Git.

What if I lose my API key?

Generate a new one in the dashboard. The old key keeps working until you revoke it, so revoke it manually to disable.

Troubleshooting

Command not found

Make sure your $PATH includes the npm global bin folder:

bash 
echo $PATH
# should include the npm global bin folder

401 Unauthorized

Your API key is invalid or revoked. Run hh logout then hh login <new-key>.

Subdomain is reserved

Common subdomains like www, api, admin, dashboard are reserved. Pick another name.

Subdomain owned by another user

Each subdomain is unique. If someone else has mysite, choose a different name (e.g. myportfolio).

Deploy stuck / timeout

Check your internet connection. If you're uploading many images, try --dir with a smaller folder, or compress images first.
